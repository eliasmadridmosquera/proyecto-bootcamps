# Proceso: registro de decisiones

## Decisiones confirmadas

Todas confirmadas por el usuario.

- **D1: Seis casos de uso.**
  1. Cargar archivos del año y obtener el cálculo (analista).
  2. Revisar tableros de cada fase (analista).
  3. Registrar una anomalía no corregible (analista).
  4. Publicar resultados del año (analista).
  5. Consulta de tableros finales de todas las carreras (Rectorado).
  6. Consulta de tableros de las carreras de su facultad (Decano).

  Rectorado y Decano van separados por tener una regla de acceso distinta; cada caso tiene un solo resultado observable.

  Contexto:
  - El sistema calcula las seis fases (desde los contratos del personal hasta el costo por carrera y el superávit/déficit).
  - Error de archivo: falta información obligatoria; no se calcula y se muestra un mensaje con referencia.
  - Anomalía de datos: datos procesables con inconsistencias; se calcula y el analista las revisa.
  - Ante una anomalía, el analista corrige y vuelve a subir, o la deja registrada si el dato de origen tiene la irregularidad; hoy no se registran.
  - Anomalías registradas: solo las ve el analista.
  - Usuarios con usuario institucional y rol; se asume que están identificados y que el Decano tiene facultad asignada (cómo se hace, decisión posterior).

  Fuera de la primera versión (mejoras futuras, sin casos de uso): roles Webmaster y Visitante; gestión de usuarios; promedios institucionales para Decanato; que las autoridades vean anomalías registradas; conexión directa a la base de datos institucional; integración con identidad institucional.

- **D2: Cálculo de las seis fases todo seguido.** Si falla un control, se detiene en esa fase y muestra cuál. Rectorado y Decano no ven resultados hasta que el analista publica; antes de publicar, el analista revisa todo (tableros de cada fase y anomalías). Si corrige y resube, se recalcula todo. Si se detecta una anomalía tras publicar, se recalcula y se publica de nuevo; mientras tanto ven lo último publicado.

- **D3: "Publicar los resultados del año" es un sexto caso aparte** (resultado propio: Rectorado y Decano pasan a ver los tableros finales).

- **D4: El analista sube todo el conjunto del año de una vez.** Si falta un archivo obligatorio no se calcula y se indica cuál; para corregir se resube el conjunto completo. Pendiente: lista exacta de archivos y datos obligatorios y archivos de apoyo. Mejora futura: reemplazar un solo archivo.

- **D5: El cálculo nuevo reemplaza al anterior.** Rectorado y Decano ven lo último publicado hasta que se publique el nuevo; los registros de anomalías pertenecen al cálculo en curso y se vuelven a registrar al recalcular. Mejoras futuras: historial de publicaciones, comparar con el cálculo anterior, conservar anomalías entre cálculos.

- **D6: Respuestas del usuario a las preguntas abiertas del caso 1.**
  - El analista indica el año al subir el conjunto.
  - Las seis fases, en orden: (1) contratos: sueldo de cada persona por periodo; (2) cargas: horas de clases de cada persona, incluida la que queda del periodo anterior; (3) costo de cada carga: el sueldo repartido entre las horas; (4) costo por categoría: ese costo agrupado por tipo de actividad; (5) gestión docencia: el costo de gestión por estudiante y carrera; (6) costo de clases y superávit o déficit por carrera.
  - Cada fase aplica controles (cuadres entre totales). Cada control termina en ok, aviso o falla: una falla detiene el cálculo; un aviso no lo detiene.
  - Con un control en falla, el analista ve los tableros de las fases ya calculadas para buscar el origen del problema.
